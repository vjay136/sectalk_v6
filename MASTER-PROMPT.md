# SecTalk master product and engineering prompt

Build SecTalk by Eagle Security as a production-oriented, multi-tenant communication and collaboration service. Treat this specification as the single implementation brief. It consolidates the Principal Software Architect, Vercel-first AI-Native Engineer, and Principal Full-Stack and Security Architect briefs. Each section records the target capability. A release can claim a capability only when its implementation, deployment dependencies, permissions, and acceptance checks are verified.

## 1. Product strategy and adoption

Serve people who need control over who contacts them and organizations that need practical communication and governance. The product combines private messaging, reliable calling, meetings, collaboration, file protection, safety intelligence, administration, and subscription billing. Design for individual, family, community, creator, SMB, healthcare, school, enterprise, security-team, and SOC users. Individuals need quick verification, understandable privacy, and safe contact approval. Family administrators need invitation and recovery controls. Community operators need moderation and spam control. Small teams need coordinated work and simple billing. Schools and healthcare organizations need access control, auditability, retention, and accessible workflows. Enterprise administrators need SSO and policies. Security and SOC operators need scoped investigations, evidence, and escalation.

Use Signal's trust, Telegram's flexible messaging, Slack's team collaboration, Teams' organization controls, Discord's community organization, Proton's privacy, and Zoom's meeting reliability as reference points. Design original SecTalk surfaces. Use onboarding, referrals and invitations, team expansion, collaboration routines, useful notifications, and security assurances as growth and retention loops. Measure first accepted contact, successful first call, retained workspace activity, delivery latency, call recovery, conversion and renewal, report time-to-action, false positives, and enterprise adoption without collecting raw private message content for analytics.

## 2. Information architecture and interaction

Public routes cover landing, pricing, product tour, security, compliance information, help, and applicable legal pages. Authentication covers signup, confirmation, sign-in, MFA, passkeys, device enrollment, and recovery. The user application groups Inbox, Calls, Meetings, Rooms, Workspaces, Tasks, Calendar, Files and Vault, Search, Notifications, Safety, Profile, and Billing. Workspace navigation includes members, teams, roles, policies, devices, integrations, evidence, billing, audit, and reports according to permission. Keep platform administration and SOC views separately gated. Add keyboard-accessible navigation and command search. Desktop uses a persistent rail and contextual panes. Mobile prioritizes focused views and reliable back navigation.

Use a calm navy/cyan brand, high-contrast states, dark and light themes, legible typography, a consistent spacing scale, responsive tables, cards, drawers, menus, and prompts. Give each action a loading, empty, success, retry, or actionable error state. Use accessible names, visible focus, contrast checks, reduced motion, and comfortably spaced targets. Show keyboard actions when relevant and require deliberate confirmation for destructive administration.

## 3. Messaging, rooms, and tasks

Support accepted-contact direct messaging, group chats, public-within-tenant and private rooms, channels, communities, broadcasts, and admin-moderated channels. Model memberships and role changes, room policy, pins, announcements, threads from messages, mentions, reactions, and permission-safe rich previews. Implement pending/queued, sent, delivered, read and failed states, with policy-controlled receipts. Use idempotent client message IDs, a durable offline retry queue, stable ordered cursor pagination, and deduplicated reconnect backfill. Permit sender edits and deletes only within policy; preserve necessary edit/change history and respect redaction, tombstones, and legal retention. Search accesses only authorized items.

Allow tasks from messages, assignment, status, checklists, due dates, completion events, and task audit. Support notes, polls, calendar events, reminders, and private or shared workspace views. Treat secret, timed, anonymous, retention-controlled, and forward-protected modes as distinct policies with explicit UI disclosure and threat-model limits. Never promise screenshot or forwarding prevention where the browser cannot enforce it.

## 4. Calls, meetings, and WebRTC

Support voice and video, device selection, camera and microphone controls, screen sharing, audio-only fallback, call state and quality indicators, and network degradation guidance. Support scheduled and ad-hoc group meetings, invite and join permissions, waiting rooms, host controls, attendance, captions and transcription, recording and consent, notes, whiteboards, breakout rooms and raise-hand controls. Keep calls and meeting admission separate from frontend rendering. Set an explicit state machine from idle through ringing, connecting, active, reconnecting, failed, and ended, with idempotent session transitions.

Use versioned signaling with authenticated session and participant IDs. Buffer trickle ICE until the active remote description is ready, reject stale generations, deduplicate signals, serialize offer/answer, and handle glare. Configure STUN and TURN through authorized short-lived credentials; test direct and relay-only paths over UDP and TLS. Design bounded retries and backoff, ICE restart, liveness, reconnect and network handoff, late joins, failed permissions, cancellation, background wake, and safe leave. Use a media service or SFU for groups and keep media traffic outside Vercel. Monitor loss, jitter, and reconnect metrics without collecting media. Store recordings/transcripts in access-controlled object storage with retention and consent. Never turn on recording silently.

## 5. Files, vault, and search

Use private object storage for attachments, avatars, recordings, exports, and vault objects. Bind metadata and object paths to account or tenant and parent scope. Apply per-type and per-plan size limits, quarantine until a scanner clears uploads, safe previews, download permissions, short-lived links, access logging, deletion, retention, and legal holds. Keep encrypted user vault objects separate from managed shared uploads. Encrypt vault content and filenames on the client with versioned authenticated encryption and a documented key strategy. Make the recovery limitation visible and keep keys out of logs and storage.

Search authorized direct chats, rooms, messages, files and metadata, tasks, meetings, and permitted audit entities. Provide keyword snippets and sender, room, date, type, and status filters. For data requiring E2EE, use client-side search or permitted server metadata. Process indexing and change events through an idempotent queue at scale. Enforce access at query time and retract deleted, redacted, quarantined, and expired data from results.

## 6. Presence and notifications

Support online, away, busy, and offline. Use rate-limited, expiring, opt-in presence and scoped audience checks. Provide durable in-app notifications, category preferences, mention and direct-message priorities, mute, snooze, browser push, and email where enabled. Use tenant-scoped recipient selection, deduplication, retry/backoff, dead letter handling, read state, and minimal payloads. Honor blocks, deleted content, workspace policy, and preferences. Keep push notifications and mail credentials server-side.

## 7. Identity, tenancy, and encryption

Support verified email/password and recovery, phone, social sign-in (Google, Microsoft, GitHub, Apple), authenticator MFA, recovery codes, passkeys/biometrics, and enterprise SSO when configured. Bind trust to verifiable device and authentication state. Support user-managed sessions and devices, secure revocation, step-up for sensitive changes, risk checks for abnormal behavior, IP reputation, VPN/proxy/TOR and impossible travel using minimized data with retention. Use least privilege, RBAC and policy-based ABAC, workspace and tenant isolation, scoped authorization, and administrator separation. Treat every request, object, invitation, session, upload, and webhook as potentially untrusted.

Use mature reviewed end-to-end protocols for chats requiring E2EE. Specify key exchange, verification, forward secrecy, rotation, device enrollment, device removal, and an explicit recovery model. Keep ciphertext and keys separate. Managed threat analysis and search cannot silently decrypt E2EE content. Permit deliberate evidence disclosure with consent. Secure hosted signup confirmation must check a real one-time token and acknowledge success with a valid sign-in URL. Support narrowly allowed redirects, including separate release environments.

## 8. Threat engine, moderation, and SOC

Assess consented or authorized text, links, attachment metadata, QR content, invites, login patterns, and device events for harassment, impersonation, phishing, credential theft, fake OTPs, fraud, crypto scams, unsafe URLs and redirects, homographs, spam, malware, and abuse. Use deterministic checks, verified scanning and reputation sources, and bounded AI classification or summaries where policy permits. Separate explainable risk, confidence, and evidence. Define thresholds for advisory warnings, quarantine, and human escalation; use false-positive review, reviewer feedback, and appeal. Limit prompts to necessary redacted evidence, treat supplied content as data, and validate structured model output. AI never grants permissions or overrides controls.

Provide user reports, blocks, review queues, evidence snapshots, assignment and escalation, policy-scoped remediation, audit, and deletion/retention with holds. SOC modules cover security events, users/devices/sessions, threat trends, risk views, abuse patterns, suspicious content, organization policy, audit, analytics, billing access, and flags. Scope read and write actions separately, require MFA for sensitive roles, record who acted and why, allow reversible measures where practical, and design evidence export with integrity and access verification.

## 9. Billing and subscription policy

Use Free, Basic, Professional (Pro), Business (Team), and Enterprise tiers. Define entitlement and seat capacity enforcement centrally. Support monthly and annual tiers, checkout, trials, coupons, upgrades/downgrades, prorations, renewals, failed-payment recovery, a clearly bounded grace period, cancellation, refund workflow, invoice and receipt history, sales tax/GST, and seats or measured usage. Include provider adapters for Stripe, Razorpay and Cashfree where enabled, with cards, UPI, net banking, or wallets as supported. Keep contracts, finance visibility, procurement, quotes and enterprise invoices separate from self-service. Signed, timestamped, idempotent webhooks and reconciliation determine paid entitlements. Keep test and live credentials isolated.

## 10. Data model and contracts

Use managed Postgres, transactional migrations, object storage, stable indexes, and immutable or append-only audit events where required. Model users, profiles, tenants, organizations, workspaces, rooms, memberships, invitations, messages, ciphertext/key envelopes, edits, reads, reactions, attachments, files, recordings, calls, signals, meetings, attendance, notifications, tasks, policies, devices, sessions, passkeys, MFA, billing/usage, invoices, payments, coupons, referrals, subscriptions, entitlements, risk events, reports, case evidence, audit, user/org preferences, feature flags, integrations, backups, and support. Establish tenant keys, FK consistency, creation/update metadata, explicit soft deletion, expiration, legal holds, and retention jobs. Minimize collection and distinguish analytics from operational data.

Define typed versioned APIs or RPCs for auth, users, messaging, rooms, calls, meetings, files, tasks, search, notifications, billing, threats, administration, analytics, audit, and integrations. Use consistent input validation, authorization, stable errors, pagination, idempotency keys and rate limits. Realtime event contracts include message.created/edited/read, call.started/ended, meeting.admitted, threat.detected, device.trusted/revoked, task.completed, subscription.created/updated, and invoice.paid. Scope fanout by tenant, recipient, and session, and use minimal hints when durable state can be read separately.

## 11. Architecture, operations, and deployment

Use a TypeScript Next.js App Router monorepo on Vercel with strict checks, typed shared modules, reusable UI, focused domain logic, separate transport, Supabase managed Auth/Postgres/Realtime, private object storage, and transport/media workers where required. Use server endpoints for privileged credentials, provider calls, verified webhooks, and policy-controlled media tokens. Use edge routing and headers where appropriate. Lay out independently testable modules for identity, security, messages, rooms, calls and meetings, files, search, notifications, threat, billing, admin, analytics, and audit. Preserve the current npm workspace build unless a controlled package-manager migration is necessary. Do not duplicate state across services unnecessarily.

Plan global ingress/load balancing, safe hot metadata and permission caching, per-user and per-tenant rate limits, async durable jobs, event outbox, observability, and external long-running workers where needed. Use separate local, preview, staging and production credentials and data when available. Require release-specific Vercel projects, branches and tags when releasing side by side. Use CI, reversible schema rollout, canary/blue-green strategy, rollback checks, observability and redacted logs, alerts, tested backups/restore, disaster recovery, failover, traffic and storage limits, and defined SLOs. Measure call quality, latency, delivery, abuse and operational health with privacy-preserving counters.

## 12. Release and acceptance gates

For each feature document purpose, scope, prerequisites, user action, system response, permissions, edge cases, observable events, UI states, acceptance tests, and implementation notes. Use feature flags for pending operational dependencies. Verify domain and edge URL configuration, payment signatures and lifecycle, role isolation, data participation, account recovery, real SMTP receipt, safe file handling, E2EE boundaries, accessibility, low-bandwidth and cross-network calls, load, retry, failure injection, backup restoration, and rollback. Keep unit, integration, browser, payment, call-network, access-control and observability tests reproducible. Never represent provider-dependent media, paid billing, compliance, or cryptographic features as released before their acceptance checks pass.

Plan milestones for foundation, identity and security, collaboration, enterprise readiness, and scale. Track tradeoffs and technical debt. Reuse existing behavior and contracts where appropriate. Resolve ambiguity in this order: security, isolation, reliability, integrity, usability, performance, developer ergonomics. Ship only working behavior and name coverage gaps and pending infrastructure in release notes.
