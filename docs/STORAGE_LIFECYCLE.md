# Storage classes and lifecycle

| Class | Private bucket and object key | Access and lifecycle |
| --- | --- | --- |
| Direct chat attachments | `sectalk-chat-files/<attachment UUID>` | Writing and downloading require a live attachment grant. Existing password-protected share links use the attachment API and retain their own expiration and use limits. Soft deletion closes ordinary access immediately. The attachment purge route removes eligible bytes after the 24-hour grace period. Unpublished uploads expire after their staging or scan-review window. Active holds defer deletion. |
| Meeting recordings | `recordings/<meeting UUID>/<recording UUID>/<media filename>` | The recording API checks meeting access and individual capture approval before serving completed media. The signed egress reconciliation flow deletes discarded captures after egress settles. Completed recordings retain their existing access and have no automatic expiration. |
| Profile avatars | `sectalk-avatars/<account UUID>.jpg` | Existing profile visibility and relationship rules govern reads. The account owner replaces the same object or explicitly removes it. The avatar remains until replacement or removal. |
| Generated exports | `sectalk-exports/<artifact UUID>` | Signed audit JSON, operational report CSV, and security report CSV/PDF downloads save immutable bytes when private Storage is configured and capacity is available. The initial download still works during a Storage outage. Saved exports remain readable for up to 24 hours by their requester with current access to the source. |

Resumable direct attachments use private database chunks of at most 256 KiB against the sender’s existing staged quota reservation. The chat Retry action continues from the last verified offset while the file is still available in the tab. Finalization verifies the full file before storing it, and the existing publication path applies file inspection and malware scanning. The protected attachment purge removes abandoned chunks after their 15-minute staging window, allowing any active finalization lease to finish.

Workspace files use the separate private attachment bucket `sectalk-workspace-files/<workspace UUID>/<file UUID>`. Active workspace members access them through Workspaces → Files. Uploads are capped at 4 MiB per file and require a clean scan. Each workspace can reserve up to 200 files and 64 MiB. Identical files use independent objects. The uploader sees a duplicate advisory only when eligible bytes already exist in the same workspace.

Room files use `sectalk-workspace-files/<workspace UUID>/rooms/<room UUID>/<file UUID>` and are available through the room’s Files tab. The file endpoint resolves the room’s current access before serving bytes. Uploads use the same file size and scan checks, with a separate limit of 100 files and 32 MiB per room. The workspace maintenance route also leases up to 12 room files for cleanup per run.

Schedule a protected internal POST to `/api/workspace-files/maintenance` using `SECTALK_FILE_PURGE_SECRET`. Each run leases up to 12 files for removal or fingerprint backfill. Backfill reads existing Storage bytes and records a workspace-scoped fingerprint. Removed, orphaned and abandoned workspace uploads are eligible for cleanup once any active write lease has passed.

Workspace file history records publication, file details views, completed server downloads, and creation of authenticated workspace links. The uploader can see their own history while an active member. The workspace owner can enable administrator access after verifying their authenticator. Administrators must verify their own authenticator to read that history. Events remain available for 90 days after recording, including after file removal. Maintenance prunes expired activity in bounded batches and keeps retired file identifiers from activating old links.

An initial export response includes `X-SecTalk-Export-Location` when the artifact was saved. Send the requester’s current bearer token to that relative API URL for another download. The response keeps the original filename, MIME type and bytes. Audit downloads also check current access to the rooms represented in the export. Clients are denied direct Storage reads and signed URL creation. Each saved artifact is limited to 1 MiB and each requester can have at most 20 reservations.

Schedule a protected internal POST to `/api/exports/purge` using `SECTALK_FILE_PURGE_SECRET` and the same Storage service credentials used by attachment cleanup. Each invocation leases at most 20 expired artifacts, removes their Storage bytes and confirms metadata deletion. Failed removals retry after the lease expires. Interrupted exports without a completed reservation become eligible after ten minutes. Expired exports are inaccessible even while cleanup is pending.
