# Stripe webhook delivery and reconciliation

Configure Stripe to send the SecTalk webhook the subscription created, updated, paused, resumed, and deleted events, plus Checkout Session completion for card-required workspace trials. Use the endpoint-specific signing secret in `STRIPE_WEBHOOK_SECRET` and the matching Stripe API credential in `STRIPE_SECRET_KEY`. The app verifies the original request bytes and signature timestamp before accepting a supported event. Stripe signature retries can have fresh signature timestamps. The Stripe event ID, signed payload hash, event time and resource remain the same across retries.

SecTalk stores a receipt for each admitted event. The receipt contains the provider resource ID and a digest of the signed request. It omits the request payload, card details, and customer email. The receipt and the billing or trial update commit together. An expired processing lease can be reclaimed. Completed deliveries return success without calling Stripe again. An event older than 30 days is no longer eligible and receipts are kept for 31 days.

Subscription events retrieve the current Stripe subscription before applying billing state. This protects against out-of-order snapshots, including stale deletions. The trial path verifies a successful SetupIntent and applies the result only to the matching server-stored Checkout session and valid reservation. It creates no charge.

Configure a private scheduler to POST `/api/billing/reconcile` with `Authorization: Bearer <secret>` using the dedicated `SECTALK_STRIPE_RECONCILE_SECRET` of at least 32 bytes. Each pass claims up to eight known Stripe subscriptions and retrieves current state using the same provider credential. Confirmed subscriptions become eligible after one hour. Unavailable or mismatched results retry after five minutes. Provision enough schedule capacity for the number of subscribed accounts and monitor the returned processed and synchronized counts. Reconciliation checks the stored account, customer and subscription binding and leaves billing state intact on mismatches or provider failures. New subscriptions enter through verified webhooks. Reconciliation repairs provider drift for linked subscriptions.

The local fixture uses the Stripe SDK, synthetic signatures, and loopback HTTP. Hosted configuration requires independent verification of endpoint events, live/test credential pairing, and scheduler delivery.
