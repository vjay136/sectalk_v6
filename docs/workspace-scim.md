# Workspace directory provisioning

Enterprise workspace owners can open **Workspaces → Integrations → SCIM**, verify their authenticator, and generate a SCIM bearer token for a verified domain. Before enabling the feature, configure the server-only `SECTALK_SCIM_SERVICE_KEY` with the Supabase service credential for the app's project. Use the displayed HTTPS base URL and token in your directory provider. Tokens expire after 180 days. Rotating or revoking a token ends its use immediately. A token is scoped to one workspace and stops working if its owner loses authority, the domain loses verification, or the Enterprise entitlement ends.

The SCIM 2.0 endpoints support Users and Groups create, read, update and delete, common PATCH operations, pagination, equality filters on user name, group display name and external identifier, and ServiceProviderConfig. Directory connectors should use the verified email as an immutable user name. You can create identities and assign groups before the user signs up. An enabled pending identity is active in SCIM but has no app account or workspace access. After completing signup and creating a profile, the user opens **Workspaces**, requests a new verification link, and opens it in the same browser. Allowlist the exact `/auth/scim-claim` URL at your app origin in Supabase Auth and enable native email magic links with PKCE. The claim requires a fresh native verification session for the confirmed address. Once attached, current group assignments and ordinary workspace access take effect.

Groups created by SCIM appear in the workspace directory. Deactivation removes workspace membership, attached group memberships and pending group assignments. Reactivation checks workspace seat limits and does not restore removed group assignments. The provider cannot adopt existing workspace members, modify privileged members, or reactivate someone manually removed or suspended by the workspace.

SecTalk account creation, account credentials, and memberships in other workspaces remain separate from SCIM. The endpoints do not offer nested groups, SCIM bulk, custom schema discovery, arbitrary filters, password updates, or general identity-provider certification. Test your connector against the documented operations before enabling automatic provisioning. The workspace audit lists token rotations, revocations and successful provisioning changes.
